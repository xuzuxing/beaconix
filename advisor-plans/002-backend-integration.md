| L1/L2 缓存与 ETag | v2 缓存保存经过脱敏的快照，取缓存前重新授权，返回时按当前角色投影；无权请求不返回旧 304 |
| 第一方任务附件 | PRIVATE；先授权上传，存储后在元数据事务再次复核；下载校验当前访问及可信任务对象路径 |

| 开发者 API | PAT 使用当前有效用户与项目策略并叠加 scopes；普通 JWT API 拒绝 PAT；API Key 使用真实机器主体，不伪造创建者用户 |
| 通知 | 显式 ACCOUNT/ORGANIZATION/PROJECT/INVITATION 范围；历史列表、计数及写操作应用当前可见范围；行政通知限制 OWNER/ADMIN |
| worker、SSE、提醒 | 当前资格复核、事务授权时间、租约归属及发送前续租；本地 SSE fan-out 再验证；提醒不靠负责人/关注者绕过授权 |
| 公开状态页 | 保持公开资源例外；排除已删除组织/项目/监控，目标脱敏，不宣称受私有项目 ACL 控制 |

## 验证边界

- Jest 包含真实 Nest/JWT/ProjectAccessGuard/ValidationPipe 的负向 HTTP 测试、父子绑定、撤权/降权/304、双副本 L1/L2、存储隔离、通知租约及嵌套查询过滤。
- 这些 HTTP 测试使用模拟数据库，不能证明 PostgreSQL 外键、触发器、锁竞争或事务回滚。
- `test/project-access/` 独立数据库验收不读取 `.env`，不回退 `DATABASE_URL`，拒绝缺失、危险、非空或身份不符的数据库；不 reset、不 drop，不以 skipped 代替验收。
- 实际执行结果统一记录在设计末尾；未执行项目不得标记通过。
- 2026-10-13：全量 Jest 123 suites / 1662 tests、离线验收检查 130 tests 通过；type-check、无 `--fix` 全仓 lint、build 通过。
- PostgreSQL/HTTP harness 已编写；两条实际命令均因缺少测试库配置在连接前 exit 1，不能算数据库验收通过。完整数据库矩阵仍有未编写用例，详见 [验收说明](../test/project-access/README.md)。

## 私有存储配置

本地设置 `STORAGE_PRIVATE_ROOT`，默认 `storage/private`。该目录不能映射为静态目录，也不能通过反向代理、共享卷、符号链接或其他服务对外公开。公开素材仍使用 `STORAGE_LOCAL_ROOT`。

使用 OSS 时设置 `STORAGE_OSS_PRIVATE_BUCKET`，必须与 `STORAGE_OSS_BUCKET` 不同。部署时另行验证 bucket policy、匿名读取、CDN 缓存、签名有效期和历史路径。代码中的 private ACL 不足以证明部署的 bucket/CDN 没有公开旁路。

撤权无法追回已经下载的文件。已发出的签名链接在其有效期内仍可能使用；代码限制窗口不超过 300 秒。EXTERNAL 文件的第三方分享权限不由 Beacon 管理；UNKNOWN 历史附件不得下载，直到完成受信回填。

## 发布前执行

1. 准备独立 disposable PostgreSQL 空库，完成新装、旧库升级、真实 HTTP、约束/触发器及并发验收。详细变量与脚本见 `test/project-access/`。
2. 管理员确认存量普通成员的逐项目授权清单，不自动把全部项目授予全部组织成员；旧待接受邀请需重发。
3. 为历史通知确定可验证范围，不确定的记录保持 UNKNOWN；为旧附件迁移私有物理对象与元数据，阻断旧公共对象 URL/CDN，并核验无匿名访问。
4. 停止旧副本与 worker，统一应用新版本和迁移；不得把新增 schema 单独发布给仍使用旧权限的应用。
5. 前端按其规划对接新权限契约。此次只实现后端，不修改前端源码。
6. 发布后复测撤权、成员重新加入、缓存、SSE、开发者凭证和私有下载；回滚不得重新开放旧的组织级全项目权限。

没有执行业务数据库迁移、生产回填、外部通知发送或存储策略修改。本文件不是生产发布批准。
