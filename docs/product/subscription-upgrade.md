# 套餐升级页面原型

## 六、前端升级页设计

### 6.1 页面结构

```text
┌─────────────────────────────────────────┐
│  套餐升级                                │
├─────────────────────────────────────────┤
│  当前生效：团队版（剩余 10 天）           │
│  到期后将降级为：专业版（剩余 27 天）     │
├─────────────────────────────────────────┤
│  ┌─────────┐ ┌─────────┐ ┌─────────┐   │
│  │ 免费版  │ │ 专业版  │ │ 团队版  │   │
│  │  ¥0/月  │ │ ¥29/月  │ │ ¥99/月  │   │
│  │ 5 监控  │ │ 50 监控 │ │ 200监控 │   │
│  │ 0 探针  │ │ 3 探针  │ │ 10探针  │   │
│  │ 3 成员  │ │ 10 成员 │ │ 无限成员│   │
│  │ [当前]  │ │[立即升级]│ │[立即升级]│   │
│  └─────────┘ └─────────┘ └─────────┘   │
├─────────────────────────────────────────┤
│  我的订阅栈                              │
│  ● 团队版  生效中  2026-10-15 到期       │
│  ○ 专业版  待生效  2026-11-01 到期       │
│  ○ 免费版  兜底                         │
└─────────────────────────────────────────┘
```

### 6.2 交互流程

```text
用户点击「立即升级」
    ↓
弹出确认弹窗（套餐、金额、时长）
    ↓
POST /orders 创建订单
    ↓
POST /orders/:id/pay 获取支付参数
    ↓
调起微信支付（wx.requestPayment）
    ↓
支付成功 → 微信回调 → 后端激活订阅
    ↓
前端轮询订单状态 → 显示升级成功
```

后端套餐、订阅、订单、支付和配额设计见 [计费设计](../design/billing.md)。
