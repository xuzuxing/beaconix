# 运行环境

## 硬件环境

本系统为服务端应用，对客户端硬件无特殊要求。服务端与探针节点的建议配置如表 2-1 所示。

表 2-1 硬件配置要求

| 部署角色 | 最低配置 | 推荐配置 | 说明 |
| --- | --- | --- | --- |
| 应用服务器 | 2 核 CPU / 4 GB 内存 / 40 GB 磁盘 | 4 核 CPU / 8 GB 内存 / 100 GB SSD | 运行接口服务与检查工作进程 |
| 数据库服务器 | 2 核 CPU / 4 GB 内存 / 50 GB 磁盘 | 4 核 CPU / 16 GB 内存 / 200 GB SSD | 存储业务数据与检查历史 |
| 缓存与队列服务器 | 1 核 CPU / 2 GB 内存 / 20 GB 磁盘 | 2 核 CPU / 4 GB 内存 / 50 GB SSD | 承载调度队列与运行时缓存 |
| 探针节点 | 1 核 CPU / 512 MB 内存 / 10 GB 磁盘 | 1 核 CPU / 1 GB 内存 / 20 GB 磁盘 | 公网可达，用于外网探测 |
| 客户端 | 任意具备 HTTP 客户端的终端 | 同上 | 无专用硬件要求 |

应用服务器、数据库服务器与缓存服务器可合并部署于单台主机用于测试与小规模使用，生产环境建议分离部署。磁盘容量主要由检查历史与附件占用，应结合监控数量与数据保留策略评估。

## 软件环境

表 2-2 软件环境要求

| 类别 | 软件 | 版本要求 | 是否必需 | 说明 |
| --- | --- | --- | --- | --- |
| 操作系统 | Linux（Ubuntu / Debian / CentOS） | Ubuntu 20.04 及以上、Debian 11 及以上、CentOS 7 及以上 | 是 | 生产推荐 Linux |
| 操作系统 | Windows Server | 2019 及以上 | 可选 | 支持本地开发与测试 |
| 操作系统 | macOS | 12 及以上 | 可选 | 支持本地开发与测试 |
| 运行时 | Node.js | 22 LTS | 是 | 应用运行环境 |
| 包管理 | pnpm | 11 | 是 | 依赖安装与脚本执行 |
| 数据库 | PostgreSQL | 16 | 是 | 主数据存储，通过驱动适配器连接 |
| 缓存与队列 | Redis | 6.0 及以上 | 是 | 调度队列、限流计数与运行时缓存 |
| 容器 | Docker | 24 及以上 | 可选 | 镜像构建与编排部署 |
| 容器编排 | Docker Compose | v2 | 可选 | 本地与单机部署 |

系统通过对象关系映射工具访问数据库，数据库表结构由版本化迁移脚本管理，升级时执行迁移即可完成结构变更，不需要手工建表。

## 网络环境

表 2-3 网络端口与出网要求

| 方向 | 端口/协议 | 用途 | 说明 |
| --- | --- | --- | --- |
| 入站 | 3000/TCP（可经反向代理改为 443/HTTPS） | 对外提供接口服务 | 生产环境应启用 HTTPS |
| 入站 | 5432/TCP | 应用连接 PostgreSQL | 仅对应用服务器开放 |
| 入站 | 6379/TCP | 应用连接 Redis | 仅对应用服务器开放 |
| 入站 | HTTPS | 探针心跳与结果上报 | 由探针节点主动发起 |
| 出站 | HTTPS | 发送邮件、推送即时消息、调用微信支付接口 | 需放通目标域名 |
| 出站 | 任意 | 对监控目标发起检查 | 需按被监控目标放通 |

系统在反向代理之后运行时，应将真实客户端地址通过标准请求头透传，以保证审计记录中的来源地址准确。

系统在运行时可对接以下第三方服务，均为可选或按需启用：

- 邮件服务商：用于发送验证码、邀请、密码重置与任务提醒邮件。
- 即时通讯平台：飞书、企业微信、钉钉的群机器人接口，用于告警送达。
- 微信开放平台：网页授权登录、小程序登录、订阅消息。
- 微信支付：订单支付与支付结果回调。
- 对象存储服务：附件存储，可切换为服务器本地磁盘。

## 客户端与兼容性

本系统对外提供标准 HTTP 接口，客户端只需具备发起 HTTP 请求的能力，不限操作系统与编程语言。接口遵循以下兼容性约定：

- 全部业务接口统一挂载在 `/api` 路径前缀下，开放接口统一挂载在 `/developer/v1` 路径前缀下，版本升级时保持路径稳定。
- 请求与响应均使用 JSON 格式，字符编码为 UTF-8，时间字段统一使用 ISO 8601 格式。
- 接口通过 `Authorization` 请求头承载访问令牌或组织凭据，不使用 Cookie 会话，便于跨端调用。
- 交互式接口文档页面依赖现代浏览器渲染，建议使用 Chrome、Edge、Firefox、Safari 的近期版本访问。
- 实时通知采用服务端推送技术，客户端需支持长连接并具备断线重连能力。
