# 软件概述

## 编写目的与适用范围

本文档是 Beaconix 烽火云监控系统（以下简称"本系统"）V1.0 的系统说明书，用于完整说明本系统的设计目标、运行环境、体系结构、功能构成、操作方式与安全机制，作为软件著作权登记的技术文档，同时作为使用人员、集成开发人员与运维人员的操作依据。

本文档的预期读者包括：软件著作权审查人员、系统使用者、二次开发与接口集成人员、部署与运维人员。

## 软件简介

本系统是一套面向多组织团队的**云可用性监控平台**，以站点与服务的可用性探测、状态判定、告警通知为核心能力，并内置组织、项目、任务等敏捷协作工作区，使监控告警的产生、处置与复盘能够与团队日常工作在同一条数据链路上完成。

系统采用多租户架构，多个组织（租户）在同一套部署实例中运行，彼此的数据、成员、配额与计费完全隔离。每个组织可以创建多个项目，在项目中配置被监控目标与告警策略；监控检查可以由服务端本地执行，也可以分发到部署在不同地域的探针节点执行，以适应跨地域、跨网络的探测需求。监控结果经过状态判定与规则计算后，形成状态变更记录与告警事件，并通过飞书、企业微信、钉钉、微信订阅消息与邮件等渠道送达责任人；对外则通过公开状态页呈现所选监控的实时状态。

围绕监控主链路，系统提供完整的运营支撑能力：套餐与订阅、订单与微信支付、配额限制、工单服务、系统级管理后台、开发者 API 凭据与开放接口，以及记录全部变更的审计日志。协作工作区则提供组织成员与四级角色权限、项目与迭代、任务全生命周期管理、评论、附件、标签、站内通知与实时消息推送，用于承载告警处置流程与团队协作过程。

本系统主要解决以下问题：

- 跨地域可用性探测难以统一管理：通过分布式探针与统一调度，使同一监控目标可在多个地域并行探测并对比结果。
- 告警噪声与漏报并存：通过规则组与规则绑定，将告警判定条件参数化，支持连续失败次数、可用率等组合策略。
- 告警送达不可追溯：每一次外部通知都形成投递记录，失败可重试，渠道连通性可测试。
- 多团队共用一套系统时的数据越权风险：通过组织级隔离、四级角色与项目级访问控制三重机制约束数据边界。
- 监控与处置过程脱节：告警可关联到项目与任务，处置过程留痕于任务活动日志与审计日志。

本系统的适用对象包括：需要统一监控多个站点与服务的中小型技术团队、提供运维托管服务的服务商、需要对自身系统做外部可用性验证的研发团队，以及需要以开放接口将监控能力集成进自有平台的集成方。

本系统的主要技术特点如下：

1. **多租户强隔离**。所有业务数据以组织为边界，租户标识由请求路径与父级资源推导后二次校验，跨租户访问在服务层即被阻断；唯一性约束按组织维度建立。
2. **双轨授权模型**。组织级资源采用"组织成员 + 角色等级"判定，项目级资源采用"项目成员 + 资源授权"判定，两套模型各自闭环，避免权限语义冲突。
3. **声明式审计**。通过装饰器声明审计实体，框架自动推断操作类型、抓取变更前后快照、脱敏敏感字段并异步落库，业务代码不承担审计职责，且审计失败不影响业务响应。
4. **队列化检查调度**。监控检查由调度器投递至消息队列，由独立工作进程并发执行，避免海量监控拖垮接口服务；检查结果与执行记录分离存储，支持失败重试。
5. **11 类协议检查器**。内置 HTTP、TCP、PING、DNS、MySQL、PostgreSQL、Redis、MongoDB、Docker、gRPC、WebSocket 检查能力，其中数据库与容器类检查在隔离运行时中执行。
6. **分布式探针体系**。探针通过设备码或令牌注册、经管理员审批后获得凭据，以心跳维持在线状态、以批量上报回传检查结果，凭据支持轮换与吊销。
7. **告警可靠投递**。告警事件与外部投递解耦，投递失败进入重试流程并保留投递记录，可人工重试，避免一次性网络抖动导致告警丢失。
8. **无状态服务与水平扩展**。接口服务不保存会话状态，令牌自包含，缓存与队列外置，可通过增加实例横向扩容。
9. **可恢复的数据删除**。组织、项目、任务、评论等核心数据采用软删除，删除后可在保留期内恢复，配套定时清理任务控制数据膨胀。
10. **接口即文档**。全部接口由装饰器声明元数据，运行时自动生成 OpenAPI 文档并提供可交互调试界面，接口契约与实现保持一致。

## 术语与缩略语

表 1-3 术语与缩略语

| 术语/缩写 | 含义 |
| --- | --- |
| 租户 / 组织 | 系统中的隔离单元，一个组织对应一个租户，拥有独立的数据空间、成员与配额 |
| 成员 | 用户与组织之间的关联关系，携带角色信息 |
| 角色 | 组织内的权限等级，由高到低为所有者、管理员、成员、观察者 |
| 项目 | 组织下的业务分组单元，监控目标、任务与迭代均归属于项目 |
| 迭代 | 项目内的时间盒，用于组织一段周期内的任务 |
| 任务 | 项目内的工作项，本系统中亦用于承载告警处置事项 |
| 监控目标 | 被探测的对象，包含地址、协议类型、检查频率与断言条件 |
| 检查 | 一次对监控目标的探测执行，产生检查结果 |
| 探针 | 部署在指定网络位置的采集程序，接受调度并回传检查结果 |
| 规则组 | 告警判定条件的集合，可复用于多个监控目标 |
| 规则绑定 | 监控目标与规则组之间的关联关系 |
| 告警事件 | 监控状态越限或恢复时产生的事件记录 |
| 投递 | 将告警事件发送至通知渠道的一次尝试，含成功与失败记录 |
| 状态页 | 面向公众展示所选监控实时状态的页面 |
| 软删除 | 仅标记删除时间而不物理删除数据的删除方式，可恢复 |
| API Key | 面向组织的外部接口访问凭据 |
| PAT | Personal Access Token，个人访问令牌 |
| JWT | JSON Web Token，本系统用于承载访问令牌 |
| OTP | One-Time Password，一次性验证码 |
| TOTP | Time-based One-Time Password，基于时间的一次性密码，用于双因素认证 |
| SSE | Server-Sent Events，服务端到客户端的单向实时推送技术 |
| RBAC | 基于角色的访问控制 |
| OpenAPI | 开放的接口描述规范，本系统据此生成接口文档 |
